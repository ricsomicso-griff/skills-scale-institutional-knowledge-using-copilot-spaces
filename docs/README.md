# OctoAcme Project Management Docs

A central entry point to OctoAcme’s project management guidance.

## Project management processes at a glance

OctoAcme manages projects through a clear lifecycle: initiation, planning, execution, release, and retrospective. Initiation validates the business need with a project one-pager, stakeholder list, success metrics, timeline, and initial risks before approving work to move into planning. Planning turns the approved initiative into a prioritized backlog, estimates scope, documents dependencies and the Definition of Done, and creates milestones and a release plan.

During execution, teams use a GitHub project board and a consistent rhythm of daily standups, weekly delivery syncs, demos, and reviews. Work is divided into small, shippable increments. Pull requests include issue links and acceptance criteria, remain reasonably small, pass automated CI checks, and receive an approval before merging. Risks and blockers are tracked in a register and escalated from the team level to the Project Manager, Product Lead, and, when necessary, the Sponsor.

Project accountability is shared among clearly defined personas. The Project Manager coordinates schedules, risks, dependencies, facilitation, reporting, and cross-team communication; the Product Manager defines outcomes, prioritizes the backlog, and measures success; Developers implement and test features and identify technical risks; and QA/Testing validates acceptance criteria and quality. Stakeholders provide inputs and approvals, while all team members contribute to transparent planning and decision-making.

Communication and quality assurance continue throughout the lifecycle. Status is maintained in a single source of truth and shared through weekly updates, stakeholder briefings, milestone reviews, and structured incident communications. Quality practices include unit and integration testing, smoke tests for critical flows, CI-based security scanning, manual QA when needed, and monitoring of velocity, delivery health, errors, latency, usage, and success metrics. Releases use pre-release checks, deployment verification, rollback planning, and stakeholder announcements. Retrospectives after sprints, releases, milestones, or incidents convert learnings into owned, time-bound improvement actions.
